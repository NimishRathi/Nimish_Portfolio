04 Projects

Password & Cert Expiry → JIRA Ticket Automation

Workplace Project · Cox Communications

n8n automation pipeline that eliminates manual JIRA ticket creation for password-expiration and SSL/TLS certificate-expiry alerts, extending a single workflow to cover both alert types.

  • Polls a shared mailbox (IMAP / Microsoft Graph API) for password-expiration and certificate-expiry warning emails; regex/JSON parser nodes extract the relevant fields (user profile, expiry date, or certificate/server details) from each alert type.
  • Calls the JIRA REST API to auto-create a task on the OMGOPS board, pre-populated with the relevant details and source email — no manual ticket creation required.
  • Fully automated, zero-touch, and runbook-driven; directly reduces manual overhead in the SSL/TLS certificate renewal lifecycle work.
n8n IMAP / Microsoft Graph API JIRA REST API SSL/TLS Cert Monitoring

Jenkins Pipeline for Automated Thales VM Server Upgrades

Workplace Project · Cox Communications

Jenkins pipeline that automates version upgrades of Thales servers across VMs, replacing a fully manual, SSH-per-node upgrade process with an on-demand pipeline gated by a single human approval step.

  • Previously: SSH into each node individually, manually run ks_upgrade.sh per version, answer its interactive yes/no prompts, reboot, and repeatedly check when the node comes back — repeated across every node and version.
  • Pipeline now SSHes into each node and drives ks_upgrade.sh across multiple versions in sequence, on demand, with no manual command typing.
  • Automated health check polls the node after reboot instead of a human manually checking availability.
  • Manual approval gate (Jenkins input step): the engineer's only remaining task is to click "Proceed" after verifying node health in the console, before the pipeline moves to the next node/version.
  • Shrinks hours of repetitive, error-prone manual typing across nodes and versions to a few clicks, with consistent steps every time and no risk of a mistyped command or forgotten reboot.
Jenkins Groovy SSH Bash Scripting Thales VM Upgrades CI/CD

Two-Tier WordPress Deployment on Kubernetes

Personal Project

Deployed a two-tier WordPress application (app tier + MySQL database tier) on a local Kubernetes cluster, replicating a production-style architecture end-to-end.

  • Separate WordPress and MySQL Deployments, each with its own Service, to isolate the app tier from the database tier.
  • Persistent storage configured via PersistentVolume/PersistentVolumeClaim so MySQL data and WordPress files survive pod restarts.
  • DB credentials and app config managed through Kubernetes Secrets and ConfigMaps instead of being hardcoded.
  • Networking set up with ClusterIP for internal DB access and NodePort/Ingress to expose WordPress externally.
  • Cluster provisioned locally using Kind (Kubernetes in Docker).
